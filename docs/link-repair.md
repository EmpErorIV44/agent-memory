# Диагностика ссылок и переименование

`memory_link_diagnostics` просматривает ссылки в читаемых источниках проекта.
Необязательные source_id и path ограничивают исходные документы; path требует
source_id. Возвращаются координаты ссылки, её target и status:

- missing: цель отсутствует или недоступна.
- ambiguous: у wiki-цели несколько кандидатов.
- stale_path: индекс удержал связь по стабильному ID, но физический путь в
  исходном Markdown больше не разрешается в ту же заметку.

Это диагностика локальных Markdown/wiki-ссылок. Внешние URL и изображения не
проверяются, фрагменты после # сохраняются, но существование heading anchor
не проверяется. Смысловые memory.relations остаются отдельной моделью.

```json
{"project":"agent-memory","source_id":1}
```

Для переименования сначала вызовите `memory_rename` без expected_plan_hash:

```json
{"project":"agent-memory","source_id":1,"from":"old.md","to":"notes/new.md"}
```

План содержит исходный хеш, manifest Markdown источника, изменённое содержимое
переносимой заметки, правки входящих ссылок, предупреждения и plan_hash.
Проверьте его и передайте plan_hash как expected_plan_hash с теми же путями.
Приложение заново строит план, сверяет файлы и права; содержимое от клиента
для применения не принимается. Новая или изменённая заметка делает план
устаревшим. Применение MCP требует --allow-write и can_write; preview требует
только чтения. Небезопасные пути, симлинки и существующая цель отклоняются.

Переписываются входящие относительные Markdown/wiki-ссылки и исходящие
относительные ссылки переносимой заметки при смене каталога. Стабильные id:
не меняются. Сохраняются подписи, wiki aliases, фрагменты, код, frontmatter и
внешние ссылки. Неоднозначные ссылки не угадываются.

Reference definitions меняются только при использовании текстовой ссылкой.
Неиспользуемые и image-only определения остаются прежними. Если определение
общее для текстовой ссылки и изображения, оно меняется ради текстовой ссылки.

Manifest проверяется перед публикацией, но блокировка файлов охватывает
отдельные записи. Конкурентные правки внешнего редактора или нового клиента
могут появиться после проверки: после переименования повторите диагностику.

Многофайловая публикация **не атомарна**. Сначала создаётся цель без перезаписи,
затем удаляется исходник с проверкой хеша, затем отдельно сохраняются repairs.
Каждая запись использует существующую защиту хеша и историю. История остаётся
привязанной к пути: архив старого пути сохраняется, новый путь начинает свою.

Ответ сообщает complete, partial, moved, applied, destination_present,
source_present, error и состояние индексации. При ошибке могут остаться обе
копии или часть исправленных ссылок. При duplicate stable ID индексация также
может отказать. Сначала осмотрите итоговые пути и applied, устраните причину,
постройте свежий план; не повторяйте старую операцию вслепую. После публикации
приложение пытается обновить индекс и memory_changes, отдельно сообщая ошибку.

Если перенос уже завершился, старый путь отсутствует и новое rename-preview
для него не построится. Оставшиеся правки из просмотренного плана можно
завершить через обычный memory_write с исходными expected_hash, проверив
текущее содержимое каждой заметки. Автоматического resume пока нет.

```sh
agent-memory link-diagnostics --project agent-memory --source-id 1
agent-memory rename --project agent-memory --source-id 1 --from old.md --to notes/new.md
agent-memory rename --project agent-memory --source-id 1 --from old.md --to notes/new.md --expected-plan-hash '<reviewed hash>'
```
