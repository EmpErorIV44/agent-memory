# Актуальность памяти между машинами

`memory_changes` и поиск обновляют индекс **локальных** Markdown. Если на другой
машине добавили знания и отправили их в Git, они появятся здесь только после pull.
Ответ MCP `memory_changes` явно содержит `remote_checked=false` и
`scope=local_markdown`: пустой журнал не означает актуальность удалённой памяти.

В начале сессии агент проверяет нужный источник:

```json
{"project":"agent-memory","source_id":1,"fetch":true}
```

Это аргументы `memory_freshness`. Ответ `freshness` содержит статус
`up_to_date`, `ahead`, `behind`, `diverged`, `unknown` или `not_repository`,
счётчики `ahead`/`behind` при доступном upstream и `checked_remote`.
`fetch=false` не обращается к сети: сравнение с локальной tracking-ссылкой
может быть устаревшим. Даже `up_to_date` при `checked_remote=false` не доказывает,
что удалённая память проверена. Проверка с fetch отражает состояние remote в
момент запроса, а не обещает отсутствие последующих изменений.

При отставании и разрешении пользователя на обновление памяти агент вызывает
`memory_pull({"project":"agent-memory","source_id":1})`. MCP требует
`--allow-write` и права записи в источник. Приложение использует настроенный
upstream, получает изменения и делает только fast-forward. При локальных
изменениях, конфликтах или расхождении веток операция останавливается.
Автоматический stash, merge-коммит, rebase и push не выполняются.
Игнорируемые локальные файлы тоже защищены от перезаписи, если upstream
начал отслеживать такой путь, например путь локального индекса SQLite.
Таймер отправки Markdown не начинает автоматически получать изменения.

После успешного pull обновляются индекс и журнал проекта. Для наблюдения новых
знаний вызовите `memory_changes` со старым курсором, обработайте страницы и
перечитайте нужные заметки. Поле `pulled=true` вместе с `indexed=false` означает,
что Git уже обновлён, но индексация завершилась ошибкой. Исправьте причину и
повторите индексацию; не повторяйте сохранение заметок.

При отсутствии сети приложение возвращает ошибку проверки; локальные файлы
остаются доступными, но актуальность относительно remote неизвестна.
История последнего push в `memory_sync_status` не заменяет эту проверку.

CLI:

```sh
agent-memory git-freshness --project agent-memory --source-id 1 --fetch
agent-memory git-pull --project agent-memory --source-id 1
agent-memory memory changes --project agent-memory --since '<предыдущий курсор>'
```
